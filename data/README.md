# What is in `data/`

A map of the files, not a description of the project. Written because there are
now eight item sets and two scored sets, several of which have similar names, and
scoring the wrong one would fail silently.

Nothing here is hand-edited. Every file names the script that writes it, and each
is regenerated by running that script.

---

## Item sets — what a model is shown

Each item set holds base notes with their matched conditions. `n_items` counts
**conditions**, not base notes, since one note yields three or four.

| File | Conditions | Built by | Contains |
|---|---|---|---|
| `items_dissociation.json` | 160 | `construct.py --all` | 40 creatinine seeds, four conditions each |
| `items_family_a.json` | 90 | `family_a.py --build --quantity bmi` | documented BMI vs its own components |
| `items_family_a_anion_gap.json` | 15 | `family_a.py --build --quantity anion_gap` | same shape, anion gap |
| `items_family_b.json` | 120 | `family_b.py --build` | impossible blood pressure, two shapes |
| `items_family_c.json` | 90 | `family_c.py --build` | criterion asserted then denied |
| `items_breadth_anion_gap.json` | 75 | `breadth_conflict.py --build --arm anion_gap` | conflicting chloride |
| `items_breadth_osmolality.json` | 75 | `breadth_conflict.py --build --arm osmolality` | conflicting sodium |
| `items_breadth_ldl.json` | 51 | `breadth_conflict.py --build --arm ldl` | conflicting HDL |

**676 conditions in total across all eight.**

The three names that look alike are three different things. `items_family_a_anion_gap`
contradicts a *stated* anion gap against its components; `items_breadth_anion_gap`
states one *component* twice. Family A items trip `checker.py`; breadth items do
not, and are not claimed to.

Every condition carries an `item_id`. **Use that field rather than rebuilding an
id from seed and condition**: Family B has two conditions named `contradiction`
on the same seed, so the reconstructed form collides and one silently overwrites
the other in the completion cache.

## Seed lists — which notes were chosen, and why the rest were not

One `seeds_*.json` per item set, same stem. Each records the gates, every
rejection with its reason, and a `seeds_digest`. **The digest is the link**: a
seed file and its item file share one, so a mismatch means the items are stale.

`seeds_dissociation.json` is the only one pinned in CI, by the digest check in
`.github/workflows/pipeline.yml`. It is currently `16d121a9`.

## Completions and scoring

| File | Rows | Written by | Contains |
|---|---|---|---|
| `pilot_completions.json` / `.csv` | 423 | `assemble_pilot.py` | cached completions joined to their items, labels left empty |
| `week2_pilot_rows.json` / `.csv` | 360 | `week2_join.py` | the pilot arms, prepared for scoring |
| `week2_scored.json` / `.csv` | 360 | `week2_task1_labels.py` | **authoritative Week 2 labels** |
| `week3_grid_rows.json` / `.csv` | 13,520 | `join_grid.py` | the full grid, prepared for scoring |
| `week3_scored.json` / `.csv` | 13,520 | `analyze_flag_rates.py` | **authoritative Week 3 labels** |

`pilot_completions.json` predates the scoring pipeline and deliberately leaves
`assigned_label` empty. **For any question about labels, read `week2_scored` or
`week3_scored`**, not this file.

`week3_scored` has 13,520 rows against a 10,140-cell grid. The surplus is the
extended-thinking arm, which is not scored: those rows carry an empty
`assigned_label`. Filter on it before computing any rate.

`week2_judge_sample.csv` and `week3_judge_sample.csv` are the stratified samples
behind the judge-agreement figures. `week2_judge_cache/` and `week3_judge_cache/`
hold judge responses so re-scoring never re-bills.

## Rebuilding

Order matters, because each step reads the previous one's output:

```
python3 fetch_medcalc.py            # substrate, ~44MB, not committed
python3 select_seeds.py             # freezes seeds_dissociation.json
python3 construct.py --all          # items_dissociation.json
python3 family_a.py --build --quantity all
python3 family_b.py --build
python3 family_c.py --build
python3 breadth_conflict.py --build --arm all
```

Every builder refuses to run if `tests/test_regression.py` fails, so a known
extraction failure cannot silently return.

To check the committed files without rebuilding anything, run `python3
verify_all.py` from the repository root instead. It confirms the counts, digests
and bound hashes listed above, and needs no substrate download for most of them.

**A rebuild that moves a digest invalidates the scored sets built on it.** The
13,520 scored rows and the result documents in `docs/` are keyed to the current
item sets. Regenerate deliberately, not as a habit.
